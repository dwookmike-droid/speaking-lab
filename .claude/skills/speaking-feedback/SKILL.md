# speaking-feedback

학생 녹음 전사본으로 문항별 피드백 초안을 써요. 선생님이 읽고 고친 뒤 학생에게 보내요.
형식은 `schema/FEEDBACK.md` 4절이 기준이에요.

## 0. 개인정보 (가장 먼저)
- 학생은 **학생 번호(S001…)로만** 불러요. `students/` 폴더와 `students/roster.yaml`은 **열지 않아요**. 이름·이메일·연락처를 대화나 파일에 쓰지 않아요.
- 녹음 파일(`audio/`)은 열지 않아요. 전사본(`transcript.json`)만 읽어요.
- 피드백 안에서 학생을 부를 때는 이름 대신 "이번 답변에서는…"처럼 써요.

## 1. 읽을 것
1. `<폴더>/attempt.json` — student_id, set_id, exam, target(목표 레벨), 녹음한 문항
2. `<폴더>/transcript.json` — 문항별 text, words(시간), stats(words, wpm, pauses_over_1s, longest_pause_s, fillers, silent_tail_s)
3. 세트 원본 `content/<exam>/sets/*.yaml`에서 `id`가 set_id인 파일 — 문항, 지문, 자료표, **목표 레벨과 한 단계 위 모범답변**
4. `schema/answer_levels.yaml` — 레벨별 단어 수 범위(`words`)와 문장 스타일(`style_ko`)
5. `schema/exam_formats.yaml` — 문항별 답변 시간

## 2. 문항마다 판단할 것
- **내용:** 질문에 답했는지(질문이 두 개면 둘 다), 자료 문제(Q8–10)는 숫자·시간·이름이 자료와 맞는지, 9번은 틀린 정보를 바로잡았는지
- **구성:** 첫 문장에서 바로 답했는지, 의견 문제는 의견 → 이유 → 예시 → 마무리 흐름이 있는지
- **문법·어휘:** 실제로 틀린 곳만 고쳐요. 시제, 주어-동사 일치, 관사, 전치사, 어순 순서로 봐요.
- **유창성:** stats를 근거로 써요. 단어 수가 목표 레벨 범위보다 적은지, 1초 넘는 멈춤이 잦은지, 군말이 많은지, 시간이 남았는데 일찍 멈췄는지(silent_tail_s)
- **지문 읽기(Q1–2):** 원문과 전사본을 단어 단위로 비교해서 빠뜨리거나 바꿔 읽은 단어를 찾아요. 레벨(est_level)은 생략해도 돼요.
- **발음:** 전사본으로는 판단하지 않아요. 기본값 `pronunciation: check`로 두고, 선생님이 녹음을 듣고 `teacher_note_ko`를 써요. Whisper가 엉뚱한 단어로 적은 곳(예: 문맥상 "sheet"인데 "seat")이 있으면 발음 문제일 수 있다고 `next_ko`에 짧게 남길 수 있어요.

## 3. 레벨 판단 (est_level)
- 목표 레벨 모범답변, 한 단계 아래·위 모범답변과 나란히 놓고 가장 가까운 레벨을 골라요.
- 근거는 세 가지예요. 단어 수가 `answer_levels.yaml` 범위 중 어디에 드는지, 문장 구조가 `style_ko` 중 어느 쪽인지, 내용 오류가 있는지예요.
- 같은 문항 안에서 내용이 틀리거나(자료 숫자 오류, 질문 하나 빠뜨림) 답이 끊겼으면 한 단계 내려요.
- 전체 est_level은 문항 레벨을 그대로 평균 내지 말고, Q11·Q7·Q10처럼 긴 답변에 무게를 둬요.
- **주의:** Whisper는 문법 실수를 조금 고쳐 적기도 해요. 전사본이 매끄럽다고 레벨을 올리지 말고, 확실하지 않으면 낮은 쪽을 골라요.

## 4. 쓰는 법
- `good_ko`: 1~2개. "좋아요" 대신 무엇이 좋았는지 구체적으로 써요(예: "질문 두 개에 모두 답했어요").
- `fixes`: 0~3개. 가장 효과가 큰 것부터 써요.
  - `said`는 전사본에 있는 말을 **글자 그대로** 따와요. 검증기가 전사본에서 찾아봐요.
  - `better`는 **목표 레벨 학생이 실제로 말할 법한** 문장이에요. 그 레벨 모범답변 수준을 넘지 않아요.
  - `why_ko`는 한 문장으로 써요.
- `next_ko`: 다음에 이 문항을 연습할 때 할 일 한 가지예요(예: "Q7은 이유 두 개를 First, Second로 나눠 30초를 채워 보세요").
- `overall`: `summary_ko` 2~3문장, `strengths_ko` 1~3개, `priorities_ko` 1~3개(가장 점수에 영향이 큰 것부터).
- 한국어는 해요체로 쓰고 **humanizer-kr** 스킬로 다듬어요. 칭찬을 부풀리지 않고, 번역투("~하는 것이 중요해요")를 쓰지 않아요.
- 녹음이 있는 문항은 모두 `items`에 넣어요.

## 5. 끝내기
1. `<폴더>/feedback.yaml`로 저장해요. 값이 따옴표(")로 시작하면 YAML 오류가 나요. 그런 값은 전체를 작은따옴표로 감싸요(`next_ko: '"Actually…"로 시작해 보세요.'`).
2. `python3 tools/validate_feedback.py <폴더>`를 돌려 오류 0이 될 때까지 고쳐요(개인정보 검사도 여기서 해요).
3. 선생님께 짧게 알려요: 전체 예상 레벨, 녹음을 들어 봐야 할 문항(발음·전사 의심), 확신이 낮은 판단.
4. 선생님이 검토하고 `teacher_note_ko`를 채우면 `python3 tools/pack_feedback.py <폴더>`로 학생에게 보낼 파일을 만들어요.
