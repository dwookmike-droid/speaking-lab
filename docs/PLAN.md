# Speaking Lab — 토익스피킹 · OPIc 모의테스트 & 학습 웹앱 계획

작성: 2026-11-02 · 기반 프로젝트: `spanish-vocab-app`(세상에없던 단어장)

## 0. 한 줄 요약
과외 학생용 웹앱이에요. 실제 시험 흐름(준비 시간 → 삐 소리 → 녹음 → 다음 문제)을 그대로 따라 하는 모의테스트와 유형별 연습·표현 템플릿·따라 말하기를 한 곳에 묶었어요. 학생이 고른 **목표 레벨**에 맞는 모범답변이 여러 가지 나와요. 학생은 녹음을 선생님께 보내고, 선생님은 녹음을 전사해서 **LLM 구독(Claude Code)**으로 피드백을 만들어 돌려줘요. 앱에는 API 키도 서버도 없어요.

## 0-1. 확정한 것 (2026-11-02, Mike)
- 대상: **과외 학생용**. 선생님이 녹음과 피드백을 관리해요.
- 모범답변: 학생이 **목표 레벨**을 고르면 그 레벨에 맞는 답변이 나와요. 레벨마다 2가지 이상 써요.
- AI 피드백: 학생 녹음을 **전사**한 뒤 **LLM 구독**으로 피드백을 만들어요. API 종량 과금이나 프록시 서버는 쓰지 않아요.
- 공개 범위: **학생에게만 공개**. 등록한 학생 이메일로만 들어올 수 있어요. 처음 들어올 때 학생 정보를 받고 **개인정보 수집·이용 동의**를 받아요.

## 1. 단어장 프로젝트에서 가져오는 것
| 단어장에서 쓰던 방식 | 여기서 쓰는 방식 |
|---|---|
| 장마다 `chNN_text.yaml` 하나 + `SCHEMA.md` + `limits.yaml` | 세트·주제마다 YAML 하나 (`content/toeic/sets/setNN.yaml`, `content/opic/topics/*.yaml`) |
| `tools/validate_text.py` (글자 수·형식·일관성 검사) | `tools/validate_content.py` (문항 수·시간·필드·글자 수 검사) |
| 콘텐츠는 Claude Code, 빌드는 스크립트로 분리 | 콘텐츠 YAML → `tools/build.py`가 `app/data/*.json`으로 묶음 → 앱은 JSON만 읽음 |
| 한국어 설명은 humanizer-kr로 다듬기 | 해설·팁·템플릿 한국어도 humanizer-kr 필수 (해요체) |
| 웹판: 빌드 없는 단일 HTML, 오디오는 해시 이름 mp3 | 빌드 없는 바닐라 JS + 문항 음성은 해시 이름 mp3 (없으면 브라우저 TTS) |
| `READY` 파일로 작업 완료 신호 | 세트별 `status: draft / ready / reviewed` 필드 |

## 2. 시험 형식 (모의테스트 엔진 기준값)
값은 `schema/exam_formats.yaml` 한 곳에 두고, 엔진은 이 파일만 읽어요. 시험 형식이 바뀌면 이 파일만 고쳐요.

### 토익스피킹 (11문항, 약 20분)
| 번호 | 유형 | 준비 | 답변 |
|---|---|---|---|
| Q1–2 | 지문 읽기 (Read a text aloud) | 45초 | 45초 |
| Q3–4 | 사진 묘사 (Describe a picture) | 45초 | 30초 |
| Q5–7 | 듣고 질문에 답하기 (Respond to questions) | 각 3초 | 15 · 15 · 30초 |
| Q8–10 | 제공된 정보로 답하기 (Respond using information) | 자료 읽기 45초, 각 3초 | 15 · 15 · 30초 |
| Q11 | 의견 말하기 (Express an opinion) | 45초 | 60초 |

### OPIc (12~15문항, 약 40분)
1. **Background Survey** — 직업·거주·여가·취미·운동·여행 선택 → 출제 주제 풀이 정해져요.
2. **Self Assessment** — 난이도 1~6 선택 → 문항 구성이 달라져요.
3. **본 시험** — 자기소개 1 + 주제 콤보(묘사 → 습관 → 경험) + 돌발 주제 + 롤플레이(질문하기, 문제 해결) + 비교·이슈.
4. **7번 뒤 난이도 재조정** — 쉽게 / 비슷하게 / 어렵게.
5. 문항마다 다시 듣기 1회, 답변 시간은 자유(권장 1~2분), 전체 시간 제한.
- 등급 표기: NL · NM · NH · IL · IM1 · IM2 · IM3 · IH · AL

> 공식 문항(ETS·ACTFL)은 옮기지 않아요. 모든 문항은 형식만 따라 새로 써요. 시험 이름은 설명용으로만 쓰고, 공식 캐릭터·로고는 쓰지 않아요.

## 3. 기능 범위

### MVP (1~3단계)
- **모의테스트 모드**: 실제 시간표대로 자동 진행, 준비/답변 타이머, 시작 신호음, 문항별 녹음(MediaRecorder).
- **결과 화면**: 문항별 내 녹음 다시 듣기, 모범답변·해설 보기, 스스로 점검표(체크리스트) 채점.
- **유형별 연습**: 토익 Q1~11 유형 하나만 골라 반복, OPIc 주제·유형 하나만 골라 반복.
- **표현 템플릿**: 유형별 답변 뼈대(도입 → 근거 → 예시 → 마무리)와 바꿔 쓰는 표현.
- **따라 말하기**: 모범답변 음성 문장 단위 재생 → 따라 녹음 → 비교 듣기.
- **기록**: 응시 이력·녹음은 IndexedDB(기기 안), 내보내기/지우기 버튼.

### 목표 레벨별 모범답변
- 학생이 처음에 목표 레벨을 골라요. 토익은 Lv5 · Lv6 · Lv7 · Lv8, OPIc는 IL · IM1 · IM2 · IM3 · IH · AL이에요. 설정에서 언제든 바꿀 수 있어요.
- 결과·연습 화면에는 **목표 레벨 답변**이 먼저 나와요. 같은 레벨 안에서 다른 내용·표현의 답변을 넘겨 볼 수 있어요(레벨마다 최소 2가지). **한 단계 위** 답변도 나란히 볼 수 있어요.
- 레벨별 작성 기준은 `schema/answer_levels.yaml`에 있어요. 유형·답변 시간별 단어 수 범위와 문장 스타일을 적어 뒀고, 검증기가 단어 수를 확인해요. 이 단어 수는 이 앱의 작성 기준이고 공식 채점 기준은 아니에요.
- 답변마다 그 레벨에서 쓴 뼈대·연결어를 표시해요. 학생이 "이 레벨은 이 정도 말하면 된다"는 감을 잡게 하려고요.
- 지문 읽기(Q1–2)는 레벨별 답변 대신 끊어 읽기·강세 표시 하나만 둬요.

### 녹음 제출 → 전사 → 구독 LLM 피드백
서버도 API 키도 쓰지 않아요. 파일을 주고받고, 무거운 일은 선생님 컴퓨터에서 해요.

```
[학생 앱] 응시 → 녹음(IndexedDB)
   └─ "선생님께 보내기" → 제출 꾸러미 .zip (녹음 파일 + attempt.json: 학생 이름·시험·세트·목표 레벨·문항별 시간)
        └─ 휴대폰 공유창(Web Share API)으로 카톡 등에 보내기, 안 되면 내려받기
[선생님 컴퓨터]
   1. submissions/<학생>/<응시ID>/ 에 꾸러미 풀기
   2. tools/transcribe.py → transcript.json (로컬 Whisper, 무료. 단어별 시간·말 멈춤·군말 같이 기록)
   3. Claude Code(구독)에서 "speaking-feedback 스킬로 <응시ID> 피드백 써줘"
        → feedback.yaml (문항별: 예상 레벨, 잘한 점, 고칠 문장 → 고친 문장, 다음 연습 과제)
   4. tools/validate_feedback.py → tools/pack_feedback.py → feedback.json
   5. feedback.json을 학생에게 다시 보내기
[학생 앱] "피드백 불러오기" → 그 응시의 결과 화면에 문항별 피드백이 붙어요
```

- **전사**: 기본은 선생님 컴퓨터의 로컬 Whisper(faster-whisper). 비용이 없고 녹음이 밖으로 나가지 않아요. 학생 앱에서 크롬 Web Speech API로 미리 받아 적는 건 보조로만 써요(정확도·브라우저 차이 때문에).
- **피드백 기준**: 내용 완성도, 구성, 문법, 어휘, 유창성(전사 시간 정보로 말 멈춤·군말·답변 길이). 발음은 전사만으로 판단하기 어려워서 "확인 필요"로 표시하고, 선생님이 녹음을 듣고 한 줄을 덧붙여요.
- **목표 레벨 기준 비교**: 학생 답변을 `answer_levels.yaml`의 목표 레벨 기준(단어 수, 문장 스타일)과 비교하고, 같은 문항의 목표 레벨 모범답변과 나란히 보여 줘요.
- **스킬**: `.claude/skills/speaking-feedback/` — 입력 파일, 출력 형식, 말투(해요체, humanizer-kr), 레벨 판단 근거를 적는 규칙. 한 번에 학생 여러 명을 처리할 수 있게 해요.
- **개인정보**: `submissions/`는 `.gitignore`에 넣어 리포에 올리지 않아요. 학생 녹음과 전사본은 선생님 컴퓨터에만 둬요.
- **음성 파일 생성**: 문항 음성은 ElevenLabs로 미리 만들어 mp3로 넣어요(단어장 웹판과 같은 해시 파일 이름).

### 학생 전용 공개 · 학생 정보 · 개인정보 동의
**접근 제한**: GitHub Pages는 비공개 사이트를 만들 수 없어요(Enterprise 요금제만 가능). 그래서 리포는 비공개로 두고 **Cloudflare Pages + Cloudflare Access**로 배포해요.
- 선생님이 Access 허용 목록에 학생 이메일을 넣어요. 학생은 이메일로 받은 일회용 코드로 로그인해요. 비밀번호를 따로 관리하지 않아도 돼요.
- 무료 요금제로 50명까지 쓸 수 있어요. 수업이 끝난 학생은 목록에서 빼면 바로 못 들어와요.
- 앱 안에서 초대 코드로 막는 방식은 쓰지 않아요. 정적 파일은 주소만 알면 열려서 실제로 막아 주지 못해요.

**처음 들어올 때 순서** (`app/onboarding`)
1. 서비스 안내 한 장: 무엇을 하는 앱인지, 녹음이 어디로 가는지
2. 학생 정보 입력
   - 필수: 이름, 이메일(로그인한 주소가 자동으로 들어가요), 휴대폰 번호, 만 14세 미만 여부, 응시 시험, 목표 레벨
   - 선택: 시험 예정일, 현재 점수·등급, 학년·직업
3. 개인정보 수집·이용 동의 (필수 항목과 선택 항목을 따로 체크해요)
4. 만 14세 미만이면 **법정대리인 동의**: 보호자 이름, 관계, 연락처. 보호자에게 확인 문자를 보내 동의 화면을 같이 보게 하거나, 인쇄용 동의서에 서명을 받아요.
5. 동의 기록(동의서 버전, 체크한 항목, 시각)을 저장하고, 첫 제출 꾸러미에 넣어 선생님께 같이 보내요.
- 동의를 철회하거나 정보를 고치는 버튼을 설정에 둬요. 철회하면 기기 안 녹음·기록을 지우고, 선생님께 철회 사실을 알리는 파일을 보내요.

**학생 정보는 어디에 있나요**
- 서버가 없어서 학생 기기(IndexedDB)와 선생님 컴퓨터에만 있어요.
- 선생님 쪽 명단: `students/roster.yaml` (git 제외). 학생 번호(S001…), 이름, 연락처, 동의 기록, 보유 기한.
- **LLM에 보낼 때는 이름을 빼요.** 전사본과 피드백 작업에는 학생 번호만 쓰고, 이름과 연락처는 넣지 않아요. `tools/transcribe.py`가 꾸러미를 풀면서 이름을 학생 번호로 바꿔요.

**동의서** — 원본 `content/legal/consent_v1.yaml` → 앱 동의 화면, 인쇄용 양식(`app/consent.html`), 문서판(`docs/legal/개인정보_수집이용_동의서_v1.md`)을 빌드로 만들어요
- 수집 항목, 목적, 보유 기간, 거부할 권리와 거부할 때 생기는 불이익을 적어요.
- 처리 위탁·국외 이전도 따로 적어요: Anthropic(미국, 이름을 뺀 전사본으로 피드백 작성), Cloudflare(미국, 로그인 이메일로 접속 제한).
- 동의서 내용이 바뀌면 버전을 올리고, 학생이 다음에 들어올 때 다시 동의를 받아요.
- 이 동의서는 초안이에요. 실제로 쓰기 전에 개인정보보호위원회 표준 양식과 비교해 보거나 전문가에게 검토를 받아요.

**선생님이 지킬 운영 규칙** (`docs/legal/운영수칙.md`)
- Claude 계정 설정에서 대화 내용이 모델 학습에 쓰이지 않게 꺼 둬요.
- 녹음·전사본은 보유 기간이 지나면 지워요. `tools/purge.py`가 기한 지난 학생 폴더를 찾아 보여 줘요.
- 제출 파일을 메신저로 받았으면 컴퓨터에 옮긴 뒤 메신저에서 지워요.

## 4. 기술 구성
- **앱**: 빌드 도구 없는 바닐라 HTML/CSS/JS(ES 모듈). 단어장 웹판처럼 가볍게 유지해요.
- **배포**: 비공개 GitHub 리포 → Cloudflare Pages (`app/` 폴더) + Cloudflare Access(이메일 일회용 코드 로그인). HTTPS라 마이크 권한이 바로 돼요.
- **데이터 흐름**: `content/**/*.yaml` → `tools/validate_content.py` → `tools/build.py` → `app/data/toeic.json`, `app/data/opic.json`
- **저장**: IndexedDB(학생 정보, 동의 기록, 녹음 Blob, 응시 기록, 불러온 피드백), localStorage(화면 설정).
- **선생님 도구**: Python(faster-whisper, PyYAML) + Claude Code 구독. 학생 앱과 분리돼 있어요.
- **지원 브라우저**: 크롬·엣지·사파리 최신. 사파리는 녹음 형식이 mp4라 둘 다 처리해요.

```
speaking-lab/
├─ CLAUDE.md                 Claude Code 작업 규칙
├─ docs/PLAN.md              이 문서
├─ schema/
│  ├─ SCHEMA.md              콘텐츠 필드 설명
│  ├─ exam_formats.yaml      시험별 문항 구성·시간 (엔진 기준값)
│  └─ limits.yaml            필드별 글자 수
├─ content/
│  ├─ toeic/sets/setNN.yaml  모의고사 1세트 = 11문항
│  └─ opic/
│     ├─ survey/survey.yaml  서베이 항목 → 주제 연결
│     └─ topics/*.yaml       주제별 문항 풀 (묘사·습관·경험·롤플레이)
├─ schema/answer_levels.yaml 목표 레벨별 모범답변 기준
├─ schema/FEEDBACK.md        feedback.yaml 형식
├─ tools/
│  ├─ validate_content.py    검증기 (레벨별 답변 수·단어 수 포함)
│  ├─ build.py               YAML → app/data/*.json
│  ├─ transcribe.py          제출 녹음 → transcript.json (로컬 Whisper)
│  ├─ validate_feedback.py   피드백 검증
│  └─ pack_feedback.py       feedback.yaml → 학생에게 보낼 feedback.json
```
